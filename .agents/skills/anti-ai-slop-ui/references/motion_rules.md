# Motion Rules

Motion should communicate state, not decorate uncertainty.

## Core principle

If motion does not help the user understand state, progress, hierarchy, or causality, remove it.

## Common AI motion mistakes

- hover animation on every card,
- scroll reveal on every section,
- animated gradient backgrounds,
- floating blobs,
- bouncing icons,
- parallax without storytelling reason,
- excessive duration/easing,
- no reduced-motion consideration.

## Good motion uses

- recording/listening state,
- processing/generating state,
- command execution feedback,
- panel open/close,
- drawer transitions,
- loading/skeleton states,
- upload/import progress,
- error/success state changes,
- live data refresh.

## Product-specific guidance

### Native macOS Utility

- subtle panel transitions,
- recording pulse if useful,
- avoid web-like scroll animations.

### Developer Tool

- command execution feedback,
- logs streaming,
- diff/apply transitions.

### Enterprise Control Plane

- drawer and modal transitions,
- loading states,
- status changes.

### Premium Wellness

- slow, soft, calming transitions,
- avoid sudden changes.

### Crypto Intelligence Terminal

- live data indicators,
- refresh states,
- risk flag transitions,
- no casino motion.

## Motion checklist

- Is every animation tied to user value?
- Does it communicate state?
- Would the UI still work if motion was disabled?
- Is reduced motion respected?
- Are durations short enough for productivity?
- Is there any decorative motion that screams AI template?
