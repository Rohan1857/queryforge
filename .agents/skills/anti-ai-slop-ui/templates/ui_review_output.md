# UI Review Output Template

Use this structure when reviewing existing UI.

## 1. Direct diagnosis

Short, blunt summary of what makes the UI look generic or distinctive.

## 2. Generic / AI-slop tells found

List detected issues:

- default component look,
- color defaultness,
- gradient/default hero,
- layout sameness,
- typography genericness,
- emoji/icons,
- excessive motion,
- weak hierarchy,
- lack of product specificity.

## 3. Why it happens

Explain the likely cause:

- library defaults,
- weak design brief,
- no visual references,
- no token plan,
- model copied common SaaS layout,
- no final quality gate.

## 4. Priority fixes

Rank fixes by impact:

1. Highest impact
2. Medium impact
3. Nice-to-have

## 5. Revised design direction

Give a concrete new direction.

## 6. Scores

- AI Slop Score: /10
- Distinctiveness Score: /10
- Implementation Readiness Score: /10

## 7. Actionable implementation notes

List concrete changes for a coding agent.

## 8. Final anti-slop gate

State what must be checked before shipping.
