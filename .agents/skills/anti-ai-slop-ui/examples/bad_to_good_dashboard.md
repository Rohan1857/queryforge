# Bad to Good: Dashboard

## Scenario

A coding agent is asked to build a dashboard for a crypto evidence/risk product.

## Bad output

### Description

- dark purple background,
- neon glowing cards,
- four generic KPI cards,
- random line chart,
- three equal feature panels,
- vague “AI insights” area,
- rounded cards everywhere,
- no evidence trail,
- no source credibility model.

### Why it feels like AI slop

It borrows generic crypto/AI aesthetics but does not support the actual job: evaluating evidence, promises, entities, and delivery status.

### AI Slop Score

8/10

### Distinctiveness Score

3/10

## Better output

### Revised direction

Crypto Intelligence Terminal / Research Archive.

### Visual system

- palette: neutral graphite or paper/ink base,
- semantic colors: delivered, unresolved, abandoned, disputed,
- typography: readable sans + mono for tickers, hashes, addresses,
- layout: entity profile + evidence timeline + source table,
- motion: live refresh/status only.

### Structure

1. Entity header:
   - project name,
   - ticker,
   - current status,
   - confidence level.
2. Score explanation:
   - not just a number,
   - evidence count,
   - unresolved promises,
   - right-of-reply status.
3. Evidence timeline:
   - dated promise,
   - source,
   - current verification status.
4. Source table:
   - URL/source type,
   - archived status,
   - confidence.
5. Operator/team panel:
   - linked entities,
   - historical delivery signals.

### Why it is better

The UI now matches the product’s trust model. It feels investigative, not decorative.

### AI Slop Score

2/10

### Distinctiveness Score

8/10
